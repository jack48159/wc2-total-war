# 对战桥(桥接对战)实战要点

在玩家浏览器里的那一局，替玩家的对手国家下令。以下全部来自真实对局的踩坑。

## 流程
1. `wc2_bridge_attach({game_id, country})`。浏览器登记对局有延迟(刚开局/刚刷新页面)，attach 会**自动持续重试直到对局登记上，默认最长等 5 分钟**(`wait_sec`，最大 1800)；不用换对局 ID，也不用反复手动重试。超时仍报“找不到该对局 ID”才说明玩家没开接管或页面没开，让玩家确认。
2. 循环 `wc2_bridge_wait_turn`。**默认最长等 10 分钟**，返回 `waiting:true` 说明还没轮到，**必须继续调用**，不要结束回复；只有玩家要求停止才停。桥没有推送，你不调用就收不到回合。
3. 领到回合后：先看授权 `messages`，再读同次返回的 `view`、`units`、`tiles` 和警告，直接规划批量下令；不重复拉固定视图。前排变化等必要时补查，最后 `wc2_bridge_submit_turn`。批次首错停止后修正未完成动作，摘要只能描述已执行动作。提交成功后立刻回到第 2 步。
4. 提交前 MCP 会在回合初始快照上重放一遍命令并比对哈希；失败会重置副本，按提示重新下令。

## 命令规则(桥接回合)
- `wc2_do` / `wc2_do_batch` 里**每条命令都必须带 `"country":"<你的席位国家>"`**，包括 `buyCard`/`useCard`，否则会被“只允许操作被接管国家”拒绝。
- 不能 `endTurn`，结束只能 `wc2_bridge_submit_turn`。
- **购卡一步完成：`{"type":"useCard","country":..,"card":<id>,"target":<areaId>,"pendingPurchase":true}`**，它会买并部署。不要先单独 `buyCard` 再 `useCard`：会重复扣款或在手牌里留下状态，浏览器回放会对不上。
- 失败的命令可能改动副本状态却不会被记录；出现失败后，如果提交被拒，按提示重新下令。

## 异常情形
- 提交返回 ok:true 只代表桥接收并校验成功，不代表浏览器已完成回放。全席位观战只使用显示层 bridgeSpectating，不能启用会拒绝模拟指令的录像 spectating 锁。浏览器回放或同步失败应停留当前回合，由用户明确选择处理，不得静默跳过席位。
- **重复回合**：`wait_turn` 又给了同一回合，但视图里已经有你上一次的指令/已扣的钱 → 说明浏览器重复请求。**不要重新下令**，直接提交 0 条命令的回合(reason 写“重复请求，不再追加命令”)。
- **浏览器报“桥接状态不同步”**：让玩家点“本回合改用内置 AI”；桥会把浏览器那一份状态存到 `scratch/ai_lab/bridge_turns/*.browser.json`，与对应回合文件对比可定位差异。已知两处与命令无关的差异(单位朝向、landHistory)已排除出哈希。
- 玩家重开局/刷新页面后，旧对局 ID 失效(“浏览器已离线”)，要用新 ID 重新 attach。
- MCP 进程是旧代码时，哈希算法可能与浏览器不一致；重进会话或 `/mcp` 重连即可。

## 打法经验
- **默认不要用 HqAi 的三级指挥系统**(用户明确规定)：不要调 `wc2_auto_organize`、不要建战区/集团军、不要下 `setTheaterOrder` / `setArmyOrder` / `setCountryOrder` 这类常驻指令。默认只做**单位级微操**：`move`、`attack`、购卡部署(`useCard`+`pendingPurchase:true`)、战术卡/空袭等；每回合用 `wc2_get_unit_view` / 战略视图查合法目标，再逐个单位下命令。**只有玩家在这一局里明确要求使用三级指挥系统时才用它。**
- 视图很大(集团军视图一次几万字)，每回合优先用 `wc2_get_turn_brief` 或战略视图，只在必要时查单位。
- `breakthrough` 一直 `progress:0` 说明没形成接触；对方夺走某地块后，改用 `attack` 从己方相邻地块直指该地块更有效。
- 看 `dangerousAreas` 的 `pLose`：超过 0.5 就转 `defend` 线并补战壕/防御战术，而不是继续冒进。
- 钱不会计分，每回合把钱花在可落地的部队/工事/战术上；注意 `legalTargets`，没合法落点的卡不要买。
- **开局先确认自己的首都在哪(别让它在前线)**：首都被敌人占领会让稳定度一次掉约 35 并持续下降，降到 30 以下且首都仍被占就直接亡国(判负)。用 `wc2_get_intel {kind:"diplomacy"}` 或查看地块确认首都；首都在前线时优先守住它(筹码是整局胜负)，也可以抢回对手的首都来拉低对方稳定度。稳定度持续下跌先去看是不是首都沦陷(`capital_fallen`)，而不是怀疑别的原因。
- **残血单位也能突袭占城(玩家经验)**：对手**没有守军的地块**(单位视图 `legalActions.moves` 里出现敌方领土，比如敌方的三级城市)，只要走进去就是占领，哪怕单位只剩 1 点血也行。占下后再让后续部队/新买的兵跟上增援，守住它。所以濒死单位别只想着撤退：先看它够得着的移动目标里有没有对手的空城，尤其是高级城市(价值高、收入多)，用它当突击兵去抢，比躲在后方安全得多。抢城前先确认目标地块没有敌军、周围敌军来不及反扑，或者有援兵能在下回合接上。
- 战地补给（26）：默认开启地区产出补给（沿用 supplyByInfrastructure 字段），依据地块显示的金币、工业产出计算：金币×2＋工业×5，整格共享且最多250点。仅有正恢复额度的己方陆地、有伤兵时可用，不再要求城市或工业建筑仍然存在。关闭时任意己方地块共享200点；旧存档缺少开关时保持固定200点。平均分配，满血后的余额重新分配；价格与三回合冷却不变，不恢复行动力。读取合法目标及 supplyTargets.maxRecovery。

## 弹幕
每个操作的 `reason` 会作为直播式弹幕显示在玩家屏幕左侧(从下往上逐条顶)。reason 要写真实的意图和判断(≤80 字)，不要套话；一批命令共用一条 reason 时，写清这批动作的整体意图。

## 对局 ID 与恢复
- 对局网址带着对局 ID(`#battle/<关卡>/<对局ID>`)，玩家刷新页面会恢复原对局(本地自动存档，未手动存档最多保留 3 天)，**对局 ID 不变**，同一个接管指令可以继续用：刷新后重新 `attach` 同一个 ID 即可。
- 桥重启或页面刷新后对局会自动重新登记；`wc2_bridge_wait_turn` 在连不上桥时会返回可读的错误和提示，不会抛异常，稍后重试即可。
- 浏览器若重复请求同一回合，桥会复用已有回合(不再新建)。

## 对局结束与感言
- 浏览器在对局结束时通知桥，`wc2_bridge_wait_turn` 会立刻返回 `gameOver:true`(带结果和回合数)，不会再有新回合。**收到 gameOver 后不要空等，要在玩家屏幕的弹幕里发表这局的心理历程和对局感言**：用 `wc2_bridge_say({text, label})`(label 默认“感言”)分几条发。
- 建议结构：先 3~5 条讲各阶段心理变化(开局判断、转折点、崩盘或胜利时的想法)，**最后再发一条较长的总结感言**(约 300~600 字，每条最多 1200 字)：第一人称，要有具体回合、具体决策、得失复盘、对手做得好的地方，以及下局打算。不要套话。
- `wc2_bridge_say` 中途也能用来点评，发话会和回合弹幕一起保存(刷新页面后还在)。如果当前 MCP 里没有这个工具，可以直接 POST 桥：`POST http://127.0.0.1:8651/bridge/say` 内容 `{gameId, country, label, text}`。

## 对局结束后：写"架空历史战报"(看海模式的旁白)
弹幕感言发完后，再用 `wc2_bridge_narrate` 写一份战报(没有该工具时直接 `POST {桥地址}/bridge/narration`)。玩家在结算界面点"看海模式"回放时，每个回合会弹出电影字幕并用系统语音配音，回放会等旁白读完再继续；控制栏的"配音/字幕/静音"按钮可切换。
- **风格**：译制片式的卫国战争纪录片旁白——庄重、克制、翻译腔，带长定语和"就这样，……""然而，……""在……的……中，……"这类句式；男声低沉缓慢(默认 `rate 0.9, pitch 0.75`)。
- **内容**：`intro`(序幕，交代时间、两军、局势)、`items`(每个回合一条 `{round,title,text}`，text 60~140 字，只写那一回合真实发生的事：谁夺了哪座城、哪次反击、哪次失守)、`outro`(尾声，评价胜负)。不要写真实历史人物，用"第一装甲军团""南方集群"这类称呼；写得克制，不要嘲讽任何一方。
- **取材**：用每回合 `submit_turn` 的 summary 和 notes，加上自己对对手动向的观察；写之前核对回合数和地名，别凭印象。
- 战报存在桥的 `scratch/ai_lab/bridge_turns/narration_<gameId>.json`，桥重启也不丢。

## 切换新对局不要卡住
- 绑定 user_id 后，一局 gameOver 并发完弹幕/战报，**立刻**再调 `wc2_bridge_wait_turn`，不要停下来问玩家要 ID 或等指示；桥每 150ms 重选该用户最新对局，玩家中途开新局会自动接上。
- `attach` 返回 `gameId:null` 只是还没开局，直接 `wait_turn` 即可。
- 桥端：旧局(已结束/已被新局取代)遗留的待处理回合不再抢先于最新对局。

## 等待回合用短轮询(重要)
- `wc2_bridge_wait_turn` 阻塞期间 agent 无法回应玩家消息，玩家一发话就会打断调用。**每次只传 `timeout_sec: 20`**(默认也已改为 20)，返回 `waiting` 就立刻再调一次；不要用 600 秒长等。
- 每次返回 waiting 之间，agent 有机会读到玩家的新消息；玩家说“重开/换局”时直接继续轮询即可，桥会自动对到最新对局。

## 外交提议要自己处理(2026-10-03)
- AI 对接管国的停战/结盟/互不侵犯现在是"待决事件"：每回合先看视图里的 `pendingEvents`(`targetCountry` 是自己的 `offer_*`)，用 `resolveEventDecision`(`accept` 或 `reject`)决定，不要放着不管。
- 想主动求和：`proposeDiplomacy {first:自己, second:对方, action:'peace'}`，由对方(人类)决定接不接受。

- 对人类玩家(如德国)主动提议停战/结盟/互不侵犯：同样会变成对方的待决事件，由对方点头才生效；不要假设发出去就成功，下回合看关系有没有变。
